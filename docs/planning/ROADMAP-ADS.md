# 广告分层治理计划（ROADMAP-ADS）

> 本文档是 [ROADMAP.md](ROADMAP.md) 的专项扩展：针对「国内手机软件广告类型大全」清单中的 60+ 种广告类型，制定分层治理方案。
> 版本号以 [ROADMAP.md](ROADMAP.md) 为准，本页只维护里程碑、周次与出口条件；文档入口见 [../README.md](../README.md)（文档地图）。
> 状态：Phase 1 进行中（步骤 A/B 已并入 main）；Phase 0（合规评审）待启动——L2/L3 启动未获批；最后更新：2026-09-26。

## 1. 背景与结论

**核心结论：不存在单一技术能屏蔽全部广告，必须采用分层防御（Defense in Depth）。**

现有 AdSkip（v3.0）只覆盖「开屏/弹窗的跳过按钮点击」这一层。要扩大覆盖面，需按广告形态拆分为五个能力层，每层参考一个成熟开源项目，各层独立发布、互不阻塞。

## 2. 五层防御架构与参考项目

| 层 | 能力 | 解决什么 | 代表参考项目 |
| --- | --- | --- | --- |
| **L1 无障碍点击层** | 遍历节点树点击「跳过/关闭」按钮 | 开屏、插屏、各类弹窗 | [GKD](https://github.com/gkd-kit/gkd)（选择器+订阅）、[SKIP](https://github.com/GuoXiCheng/SKIP)、[TapClick](https://github.com/haoweishow/TapClick)、本项目现有引擎 |
| **L2 网络过滤层** | DNS/hosts 拦截广告请求 | Banner、信息流素材、联盟广告请求 | [AdGuard Home](https://github.com/AdguardTeam/AdGuardHome)、[AdAway](https://github.com/AdAway/AdAway)、AWAvenue-Ads-Rule（规则集）、本地 VpnService DNS 形态 |
| **L3 Hook 层**（可选 Root） | Hook 广告 SDK / 传感器 | 摇一摇、扭一扭跳转、贴片跳过 | [fuck_shake](https://github.com/0x0hiii/fuck_shake)（防摇一摇，LSPosed）、[AdClose](https://github.com/Siroko/AdClose)、LSPosed 框架 |
| **L4 系统/通知层** | 通知过滤、系统级设置引导 | 推送通知广告、悬浮窗治理、锁屏/负一屏 | [push-filter](https://github.com/miuir/push-filter)、[mnblocker](https://github.com/XiaoYieXianCheng/mnblocker)、厂商 ROM 自带开关 |
| **L5 规则生态层** | 订阅分发 + 社区共建 + 快照工具 | 让 L1 规则持续覆盖新 App | GKD 订阅机制（`gkd-subscription` topic）、SKIP 的 YAML 订阅 + PR 共建、GKD inspect 快照审查 |

## 3. 能力边界（写入免责声明，对用户诚实公示）

**明确不做：**

- ❌ 激励视频「帮你跳过」——用户看广告是为换奖励，跳过损害用户利益；
- ❌ 信息流/原生/平台内容型广告的「删除」——无障碍只能点不能删节点，强行做会误触（点击 = 点广告跳转）；
- ❌ 短信/彩信广告、应用商店广告、搜索广告——不属本工具范畴；
- ⚠️ 视频贴片、Draw 信息流——仅 L2 能拦部分素材请求，UI 层无解，标注「部分覆盖」。

**合规前提（Phase 0 评审项）：**

- 现有 `ROADMAP.md`「明确不做的」声明为「只点击界面已有跳过按钮，不拦截/破解广告内容」。**L2 DNS 过滤与该条款存在张力**，启用前必须修订边界声明并明确：L2 仅拦截已知广告域名的网络请求、不改写/解密任何内容、默认关闭；
- 吸收「李跳跳」不正当竞争诉讼先例：仅点击 UI 已展示的按钮、不上架应用商店、免责声明醒目；
- 合规评审未通过前，L2/L3 不进入发布分支。

## 4. 广告类型 → 分层覆盖矩阵

| 广告类型（对应清单章节） | 层 | 方案 | 覆盖度 |
| --- | --- | --- | --- |
| 开屏广告（一.1） | L1 | 关键词 + ViewID 点击（现有能力） | ✅ 高 |
| 插屏/新插屏（一.3/4） | L1 | GKD 式选择器规则点关闭按钮 | ✅ 中高 |
| 弹窗类、悬浮窗（一.2 部分、二.2） | L1 | 选择器规则 + SafetyGuard 护栏 | ✅ 中 |
| Banner（一.2）、信息流/Draw/沉浸式（一.5/6/7）、下拉刷新（一.22） | L2 | DNS 拦广告素材域名 | ⚠️ 中（native 广告可能留白） |
| 激励视频（一.8）、全屏视频（一.11）、贴片（一.12）、导视（一.18） | L2 | 拦素材域名（部分破图） | ⚠️ 低（**不点跳过**，不破坏奖励机制） |
| 摇一摇/扭一扭/滑动互动（九） | L3 | Hook 加速度/陀螺仪回调 | ✅ 高（需 Root） |
| 推送通知广告（二.1） | L4 | NotificationListener 过滤 + 黑名单 | ✅ 中高 |
| 锁屏/负一屏/系统通知栏（二.3/6/7） | L4 | 引导关闭厂商开关（按 ROM 维护路径库） | ⚠️ 中 |
| 浏览器弹窗（二.5） | L2+L1 | 浏览器自带拦截为主，L1 兜底 | ✅ 中 |
| 短信广告（二.4） | — | 不做（系统短信 App 自带拦截） | — |
| 信息流/搜索/社交/直播/电商内容型（四） | — | 不做（见第 3 节边界） | — |

## 5. 分阶段计划（总周期约 4 个月，可并行）

### Phase 0 — 调研固化与合规评审（第 1~2 周，P0）

- **交付物**：
  - 《能力边界与免责声明 v2》——逐类型标注覆盖度（第 4 节表格），完成第 3 节合规条款评审；
  - 技术选型 ADR：L2 采用「本地 VpnService DNS（免 Root）」还是「外接 AdGuard Home」；L3 采用 LSPosed 模块还是独立 Root 方案。
- **验收**：边界声明定稿；L2/L3 启动获批。

### Phase 1 — L1 无障碍点击层（引擎增强，第 3~8 周，P0 核心）

> 详细技术方案（文法规范、匹配算法、协议 v2、改动清单、测试计划）见 [DESIGN-PHASE1-SELECTOR.md](DESIGN-PHASE1-SELECTOR.md)。

参考 GKD / TapClick 升级现有引擎（当前关键词 + ViewID 双通道是覆盖瓶颈）：

**交付节奏（2026-09-26 调整，替代原「单版本大礼包」）**：本阶段拆为 4 个可独立验收的版本——`3.0.3`（引擎内核，步骤 A/B，**代码已并入 `main`**）→ `3.1.0`（协议 v2 + 点击校验，步骤 C/D）→ `3.2.0`（快照工具，步骤 E）→ `3.3.0`（Top 30 规则 + 真机验收，步骤 F）。每版独立发版、独立回滚。

1. **选择器引擎**（`3.0.3`，步骤 A/B **已完成**）：在 `SkipRuleEngine` 上增加父子/兄弟节点关系匹配（类 CSS 选择器**子集**：`vid`/`text`/`desc` + 3~4 种关系运算符），保持纯 Kotlin 零依赖；
2. **快照工具**（`3.2.0`，步骤 E）：App 内「抓取当前节点树」导出（参考 GKD inspect + TapClick 显示布局拾取），解决规则编写靠猜；
3. **规则热扩展**（`3.1.0`，步骤 C）：复用 v1 协议（ETag/304 + JobScheduler 同步），`schemaVersion: 2` 增加选择器表达式字段，保持 v1 客户端兼容；
4. **点击结果校验**（`3.1.0`，步骤 D）：点击后 500ms 内若发生跳转外部 Intent / 页面异常切换，则回退并将该规则加入本地黑名单（防广告 SDK 劫持点击）；SafetyGuard 硬编码黑名单维持不可被云规则覆盖。

- **交付物**：引擎模块 + 覆盖 Top 30 国内 App 的首批 30 条选择器规则；JVM 单测 ≥ 60 项（当前已达 121 项）。
- **验收**：分版本执行——`3.1.0`/`3.2.0` 看工程门禁（CI 全绿 + 契约夹具双端一致 + 劫持场景单测绿）；`3.3.0` 看真机指标（Top 30 App 实测开屏跳过率 ≥ 95%，误触率 = 0，`findTarget` p99 < 8ms）。

### Phase 2 — L2 网络过滤层（第 5~10 周，P1，可与 Phase 1 并行）

参考 AdAway / AWAvenue-Ads-Rule：

1. **方案 A（推荐，免 Root）**：本地 VpnService 做 DNS 过滤，规则源直接订阅成熟规则集（AWAvenue 等，不自造轮子）；**默认关闭**，仅拦截明确广告域名；
2. **方案 B（轻量备选）**：不内置 VPN，文档引导自建 AdGuard Home / 改 DNS，本项目只做规则聚合与健康检查；
3. 服务端新增 `GET /api/v1/filter-rules` 路由，复用现有鉴权/限频/ETag 基建。

- **验收**：Top 20 App 的 Banner/信息流素材拦截率 ≥ 70%；VPN 关闭时零开销；正常业务域名零误伤（冒烟测试框架扩展回归集）。

### Phase 3 — L3 防互动跳转 Hook 层（第 9~13 周，P1，Root 可选）

参考 fuck_shake / AdClose（LSPosed）：

1. 独立 LSPosed 模块：对广告包名的加速度/陀螺仪回调投递空实现 → 屏蔽摇一摇/扭一扭跳转；
2. 可选评估：Hook 穿山甲/优量汇 SDK 落地页 `startActivity` 拦截（风险高，放后续决策）；
3. **定位为可选组件**：无 Root 用户提示不可用，主流程（L1+L2）不依赖。

- **验收**：Top 10 摇一摇广告 App 实测跳转触发率 0；模块停用后无残留。

### Phase 4 — L4 通知与系统层（第 11~14 周，P2）

参考 push-filter / mnblocker：

1. NotificationListenerService 过滤营销通知（「推广关键词 + 非联系人」启发式），默认仅静默、可恢复；
2. 悬浮窗广告：引导关闭「显示在其他应用上层」权限（无障碍无权代管，只能引导）；
3. 锁屏/负一屏/厂商推送：维护主流 ROM（小米/华为/OPPO/vivo）关闭路径图文库，设置页一键跳转。

- **验收**：通知过滤误杀率 < 1%（白名单机制），提供手动恢复入口。

### Phase 5 — L5 规则生态与运营（第 7 周起持续，P1）

参考 GKD 订阅 topics / SKIP PR 共建：

1. 管理后台增加**快照提交通道**：用户一键上传节点快照 → ADMIN_TOKEN 审核 → 入库下发；
2. 规则库按包名版本化，失效自动降级（扩展现有 schemaVersion 校验）；
3. 文档：规则编写指南 + 覆盖度矩阵公示。

- **验收**：规则月均新增 ≥ 20 条；12h 自动同步链路可用（现有 SyncJobService）。

每个里程碑走现有流程：`release/vX.Y.Z` → CI 全门禁（`assembleDebug`、`testDebugUnitTest`、`bun test`、`bun run typecheck`）→ Squash Merge → 签名 Release + `SHA256SUMS`。

## 8. 风险与对策

| 风险 | 等级 | 对策 |
| --- | --- | --- |
| 合规/不正当竞争诉讼（李跳跳先例） | 高 | Phase 0 固化边界：只点已展示按钮、L2 默认关、免责声明醒目、不上架商店 |
| 选择器引擎复杂度失控 | 高 | 只做语法子集（3~4 种关系运算符）；完整 DSL 留待后续版本；每条语法规则配单测 |
| 误触（点到支付/登录） | 高 | SafetyGuard 硬编码黑名单不可被云规则覆盖（现有设计保持）+ 点击结果校验回退 |
| DNS 过滤误伤正常域名 | 中 | 规则白名单审核、默认关、一键回滚（复用服务端规则备份轮转） |
| Root 用户占比低 → L3 价值有限 | 中 | L3 定位可选增值组件，不进主验收线 |
| 广告 SDK 反制（检测无障碍/随机化按钮 ID） | 中 | 快照工具 + 12h 规则同步快速响应；文本通道兜底 |
| 大礼包式里程碑：未发布内容堆积、真机指标阻塞无关能力 | 中 | 里程碑按「用户可见能力」切分为小版本（`3.0.3`→`3.3.0`），每版独立验收与回滚；真机指标集中在 `3.3.0` |

## 9. 预期最终覆盖度（对用户公示口径）

- **较好解决 ≈ 40%**：开屏、插屏、弹窗、推送通知、锁屏可关项、摇一摇、Banner/信息流素材拦截；
- **部分覆盖 ≈ 20%**：贴片/激励视频（仅破图、不代点跳过）、原生广告（可能留白）；
- **明确不覆盖 ≈ 40%**：内容型广告、激励视频跳过、短信、平台/搜索/电商广告。

这是技术路线的物理上限，必须在产品页与免责声明中如实公示，不宣称「全屏蔽」。
