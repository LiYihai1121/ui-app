# 广告治理分层技术决策（评审稿）

> 状态：**待评审，不代表 L2/L3 已获准进入实现或发布**。本文件对应 Issue #84。任何会影响网络流量、通知或应用行为的能力都应独立开关、可撤销、可回滚。

## 1. 目标与非目标

目标是在现有 AdSkip（Kotlin + Jetpack Compose）基础上，采用分层、可测试、尽量本地化的方式治理个人设备上的广告体验。优先复用成熟开源项目与规则集，避免复制实现代码前未审许可证、维护状态和规则来源。

非目标：
- 不破解、注入或修改第三方 App 的代码，不解密 HTTPS/TLS，不绕过付费功能或访问控制。
- 不代跳激励视频，不点击广告素材、下载按钮、购买、授权、登录或其他非明确关闭动作。
- 不承诺“全量去广告”；不能识别的广告必须明确标记为未覆盖。
- 不将通知正文、完整 URL、DNS 查询历史或节点树快照默认上传服务器。

## 2. 分层建议

| 层 | 建议实现 | Root | 默认状态 | 主要边界 |
|---|---|---:|---|---|
| L1 开屏/弹窗关闭 | 保留现有纯 JVM 规则引擎、选择器、SafetyGuard 和点击后校验 | 否 | 可由用户逐 App 开启 | 只点击可见且明确的“跳过/关闭”控件；不删除信息流/原生广告节点 |
| L2 域名过滤 | 独立的本地 `VpnService` DNS 过滤模块；订阅可审计的公开规则集 | 否 | 默认关闭，用户明确启动 | 仅能阻止命中规则的域名解析/连接；不是通用 HTTPS 内容过滤器 |
| L2 外部替代 | 可选择由用户自行配置 AdGuard Home / 可信 DNS 服务，本项目只提供说明和可选规则来源 | 否 | 用户自行配置 | 避免同时占用本应用 VPN；Android 同一用户/工作资料同时只能有一个活动 VPN |
| L3 交互跳转 Hook | 若通过单独评审，再研究独立 LSPosed 模块 | 是（通常需 Root/框架） | 不安装、不启用 | 与主 APK 分离；兼容性、稳定性和第三方 App 变更风险高 |
| L4 通知推广 | `NotificationListenerService` + 用户配置的包名/关键词规则 | 否 | 默认关闭；明确授予通知访问后启用 | 默认优先静默或归档提示，不做不可恢复删除；提供白名单和恢复入口 |
| L4 悬浮窗/系统推荐 | 引导用户进入厂商/Android 设置关闭对应权限或推荐项 | 否 | 仅引导 | 普通应用不能任意管理其他 App 的悬浮窗权限或修改 OEM 私有设置 |

## 3. L2：本地 DNS 过滤方案

### 决策建议

优先评估**非 Root、本地处理、用户手动开启的 `VpnService` DNS 过滤**。初版只实现 DNS 层，不做 HTTPS 中间人代理，不解密 TLS，不安装用户 CA，不代理非 DNS 流量。若无法在不影响正常网络的情况下正确处理 IPv4/IPv6、TCP/UDP DNS、网络切换与私有 DNS，则推迟发布，或仅提供外部 AdGuard Home 使用指引。

### 必须满足的安全与可靠性条件

- 启动前调用系统 VPN 授权流程；状态页显示过滤正在运行，并提供显眼的停止按钮。
- 默认不启用“无 VPN 时阻断网络”；服务崩溃、升级、用户停止后应关闭文件描述符并让系统恢复网络。
- 本地规则采用来源、许可证、更新时间、版本、校验值和变更记录可追溯的格式。
- 支持用户白名单/例外域名；每次更新先校验、再原子切换；规则源不可用时继续使用最后一份有效规则。
- 只保留汇总计数和必要的错误日志；默认不保存完整 DNS 查询历史，不上传用户查询。
- 测试正常登录、支付、推送、视频、下载、企业/校园网络、IPv6、私人 DNS、切换 Wi-Fi/移动网络、VPN 冲突和断网恢复。
- 误拦截应能通过一键暂停、删除例外规则或停用 VPN 快速恢复。

### DNS 过滤不能做到什么

- DNS 只能按域名做决策，不能可靠区分同一域名下的广告与正常业务；误拦可能导致 App 图片缺失、登录失败或内容空白。
- 广告与 API 使用同域名、应用内置 IP、加密 DNS/自建解析、硬编码地址或第一方投放时，覆盖可能很低。
- DNS 不会移除已下载的广告素材或 UI 节点；广告占位、留白或倒计时仍可能存在。
- 不能保证阻止每一种追踪、广告请求或系统级推广。

## 4. L4：通知推广治理

- 仅在用户从系统设置显式授予通知访问后运行；权限状态随时可查看、可撤销。
- 优先级顺序：用户包名/频道白名单 > 用户明确配置的黑名单 > 可解释的关键词规则。默认不自动按单一“推广”词删除通知。
- 首版建议仅对命中规则的通知提供“静默/折叠”选项（在系统 API 和 ROM 允许范围内）；如果系统只允许取消通知，必须显示该行为并提供恢复说明。
- 重要通知（通话、验证码、支付、日历、健康/安全、设备告警）应默认保护；提供最近操作记录，但不要保存通知正文。
- 各厂商 ROM 的通知分类和权限页面不一致，设置跳转必须有兜底说明，不假设所有机型都可自动操作。

## 5. Root / 非 Root 方案分界

### 非 Root 主线（优先）

- L1 无障碍服务：沿用现有安全护栏，用户逐 App 配置。
- L2 本地 DNS VPN：可选、明确授权、默认关闭。
- L4 通知监听：可选、明确授权、优先静默、可恢复。
- 不使用 Root 权限，不 Hook 第三方 App，不要求关闭系统安全机制。

### Root 可选扩展（独立模块，不阻塞主线）

- 仅在设备所有者明确安装 Root/LSPosed 后研究防摇一摇等交互 Hook。
- 模块与主 APK 分开构建、分开发布、独立禁用和卸载；不把 Root 检测或 Hook 作为主流程前置条件。
- Hook 方案可能因 App 更新、混淆、ROM、框架版本变化失效，且可能触发崩溃或与 App 条款冲突；先做概念验证和设备矩阵测试，不承诺覆盖率。
- 不 Hook 支付、登录、授权、反作弊、安全校验或用户奖励流程；不绕过付费与访问控制。

## 6. 开源复用与许可证治理

候选项目（仅作为调研对象，不代表已批准复制代码）：
- [GKD](https://github.com/gkd-kit/gkd)：研究规则/订阅和节点选择器设计；复用代码前核实当前许可证、版本和兼容性。
- [AdAway](https://github.com/AdAway/AdAway)：研究 hosts/DNS 过滤和规则管理。
- [AdGuard Home](https://github.com/AdguardTeam/AdGuardHome)：作为外部 DNS 过滤替代方案，不默认把服务端组件嵌入 Android APK。
- [AWAvenue-Ads-Rule](https://github.com/TG-Twilight/AWAvenue-Ads-Rule)：规则集候选；需核实当前规则许可、来源、更新频率、误拦反馈机制与分发条款。
- [LSPosed](https://github.com/LSPosed/LSPosed)：只用于可选 Root 扩展的架构调研。

复用前必须记录：仓库 URL、锁定的 commit/tag、许可证文件、版权/NOTICE 要求、修改记录、上游更新策略、规则集许可及分发限制。不得仅凭“开源”标签推断可任意复制或重新分发。

## 7. 验收门槛

- [ ] Phase 0 的合规、隐私与许可证评审完成。
- [ ] L2 设计审查通过后才开始编码；L3 需单独批准。
- [ ] DNS 测试包含允许/拦截/白名单/规则损坏/过期/网络切换/IPv4+IPv6/VPN 冲突/异常退出恢复。
- [ ] 关键正常业务域名回归集无已知误拦；误拦率与覆盖率按测试样本报告，不宣称普遍保证。
- [ ] 通知规则测试覆盖白名单、关键词误判、重要通知保护、撤销权限、恢复路径。
- [ ] 所有新功能默认关闭，用户可以查看状态、暂停、清除规则和撤销授权。
- [ ] 通过现有 CI、单元测试、契约测试和真机回归后，方可通过 PR 进入主干。
