# 独立 code-simplifier 插件 Spec

## 背景与目标

AI 在代码审查和实现中可能引入假想需求、冗余抽象，或未核实数据关系就新增查询与服务。建立一个独立、可长期维护的 `code-simplifier` 源项目；其单个公开 skill 帮助保持业务流程可读、避免过度设计，并保留既有行为。`langji-ai-marketplace` 只分发经验证的插件快照。

- 本地源码项目：`D:\Project\personal\code-simplifier`，与 `D:\Project\personal\ai-dev-protocol` 同级；新建 `main` 的初始提交 `a71f5981ad75bc1dbb0017a15eff1b32154546c5`，在 `codex/20260929-langji-code-simplifier` 隔离开发。
- 分发项目 `langji-ai-marketplace` 另有同名隔离分支；其 `docs/specs/20260929-code-simplifier.md` 规定安装入口、快照和范围。
- 初始实施不创建远端仓库、不推送或合并。完成验收后，用户另行授权合并、推送，并明确授权创建公开的 `langji3/code-simplifier`；个人已安装插件配置仍不改。

## 本次范围

1. 建立 Codex/Claude 插件清单及唯一公开 `skills/code-simplifier/SKILL.md`。描述让普通代码审查任务能自动发现它，同时避免无关任务误触发。审查只报告有证据的问题；编写/修改代码时仅在任务已授权范围内应用简化原则。
2. 通用编码原则服从目标项目风格，Java/Spring 示例说明：先理解现有实现、真实数据关系与调用方；不为假想需求新增分支、配置、查询、服务或框架；适合时用有序不可变常量表达固定选项。短小、单次调用、无独立业务含义的连续逻辑优先留在主流程；抽取需有复用、复杂逻辑隔离、事务或权限边界等具体收益，不以方法或行数少为目标。
3. 简化保持请求、返回、异常、权限、事务和副作用。共享校验和事务边界不得机械合并；删除“全部”等产品能力属于需求变化，交回项目既有流程。
4. 保留上游思想来源、署名和 Apache-2.0 许可说明；提供版本、验证和从源码向 marketplace 更新的明确路径，并验证格式与真实决策效果。

## 非目标与影响区域

- 不改 `ai-image-gen` 代码，不安装上游整包，不引入其 JS/React 专属风格或 commit/create-branch 流程。
- `ai-dev-protocol` 继续管需求、分支、spec、计划、提交、合并和交付；本 skill 不设第二套流程或隐藏状态。
- 源项目影响插件清单、skill、许可/来源说明、维护与验证文件；分发项目影响 `plugins/code-simplifier/`、Codex/Claude/catalog 入口及独立来源校验。业务 API、数据库和依赖不变。

## 实现与审查

按 skill-creator 和 plugin-creator 建立最小可维护插件；源码验证后将明确版本的内容复制成 marketplace 快照并校验相同。评估简化建议时查证真实行为与调用链；独立审查并修复发现的问题。仅为实际维护需要添加文档或验证，不预建无用目录或通用发布框架。

## 验证方式

- 运行 skill、plugin 清单格式验证，核实 Codex/Claude 只发现一个公开 skill。
- 用固定选项被动态化、单次调用小方法、共享校验、事务边界和删除“全部”选项五个情境检查决策；覆盖普通代码审查自动发现、审查不修改与修改不越界。
- 在分发项目运行 marketplace 校验、相关测试和 `git diff --check`，记录源码版本与快照一致性及未验证的真实平台行为。

## 范围变化

需要额外区域或功能时先说明并更新 spec；新远端、合并、推送和发布另行授权。
