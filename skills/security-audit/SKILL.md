# 安全审计（security-audit）

> **规则指针（唯一事实源，本文不复制正文）**
> - 安全策略与密钥纪律：[SECURITY.md](../../SECURITY.md)、[AGENTS.md](../../AGENTS.md)「提交」（不提交密钥/签名文件/构建产物）
> - 协议与鉴权契约：[docs/api/API.md](../../docs/api/API.md)
> - 分层边界：[docs/architecture/ARCHITECTURE.md](../../docs/architecture/ARCHITECTURE.md) 2.1

## 自检动作

1. [ ] 威胁面盘点：鉴权/授权、输入校验、注入、路径穿越、加密与随机、组件暴露、日志泄露、DoS、依赖
2. [ ] 每条发现附实际代码证据（文件:行号 + 关键行）；无证据不写
3. [ ] 按可利用性分级（Critical / High / Medium / Low）并附攻击场景
4. [ ] 区分「真实可利用漏洞」与「加固建议 / 坏味道」，不混写
5. [ ] 修复清单按优先级排序，每项给出最小改法
6. [ ] 已核查为安全的项列出结论与依据（防后人重复排查）
7. [ ] 残留风险如实记录（含需部署激活的机制：密钥 / 证书 / 开关）
8. [ ] 修复经最小测试 + 相关门禁验证后才算完成

## 自检：确认未出现以下情况

- 无证据的推测性结论混进报告
- 审计过程中顺手改代码（修复走独立分支 + PR）
- 把加固建议写成「漏洞」
